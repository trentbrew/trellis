# Kanban Projection for Lane Dashboard

## Goal
Add a kanban board view to the existing `trellis lane watch` dashboard, toggled from the current grid view.

## Scope
**Single file change:** `src/ui/lanes.html` — no backend changes needed. The SSE stream already provides all required data (`LaneRow.status`).

## Approach

### 1. View toggle in header
- Add a segmented toggle button (Grid | Kanban) next to the live indicator
- Persist preference in `localStorage`
- Default to grid (backward compatible)

### 2. Kanban CSS
- Horizontal scroll container with columns
- Each column: fixed width (300px), vertical scroll for overflow
- Column headers with status badge + count
- Reuse existing `.card` styles, add `.kanban` container class
- Status column colors: Active=green, Promoting=yellow, Promoted=blue, Dropped=grey (matches existing badges)

### 3. Kanban rendering
- Group `snap.lanes` by `status` into 4 buckets
- Render columns left-to-right: `active` → `promoting` → `promoted` → `dropped`
- Each column shows lane cards (same card markup as grid view)
- Empty columns show "No lanes" placeholder
- Column header: status name + count badge

### 4. JS changes
- Add `currentView` state variable (`'grid'` | `'kanban'`)
- Add `toggleView()` function bound to toggle buttons
- In `render(snap)`: branch on `currentView` to call either existing grid render or new kanban render
- Kanban render function: `renderKanban(lanes)` — groups and inserts column HTML

## Files to modify
- `src/ui/lanes.html` (only file)

## Verification
1. `trellis lane watch` — open dashboard
2. Toggle between grid and kanban views
3. Verify columns group lanes correctly by status
4. Verify cards show same info in both views
5. Verify preference persists across page reloads
