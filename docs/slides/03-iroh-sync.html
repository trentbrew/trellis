Sync Philosophy

Sync is replication, not ownership transfer. A relay may help peers connect, but it should not become the primary owner of state.

Local-first

  • Every peer owns its graph locally
  • Signs all ops with Ed25519 identity
  • Validates incoming ops before applying
  • Works fully offline — sync is additive

P2P replication

  • Iroh QUIC — direct peer-to-peer
  • WebSocket / PartyKit — browser-compatible adapter
  • Memory transport — test-only
  • All transports implement the same interface

Transport Abstraction

All sync transports implement the SyncTransport interface:

export interface SyncTransport {
  send(peerId: string, message: SyncMessage): Promise
  onMessage(handler: SyncMessageHandler): void
  peers(): PeerId[]
  connect?():  Promise
  disconnect?(): Promise
}

// Implementations:
IrohSyncTransport     // QUIC (north star)
WsTransport           // WebSocket
PartyKitTransport     // PartyKit relay
MemoryTransport       // in-process (tests)

The SyncEngine is transport-agnostic — it only knows about SyncMessage objects, not bytes.

Wire Protocol — have / want / ops / ack

The sync protocol exchanges versioned messages between peers:

peer A           peer B
  |    have(heads: {main: op4})    |
  | ─────────────────────────────→ |
  |                                |
  |    want(afterHash: op4)        |
  | ←────────────────────────────── |
  |                                |
  |    ops([op5, op6, op7])        |
  | ─────────────────────────────→ |
  |                                |
  |    ack(integrated: [op5…])     |
  | ←────────────────────────────── |
  |                                |
  |    nack(refs, reason)           |  ← if any op fails validation
MessagePurpose
haveAdvertise our head op hashes + count
wantRequest ops we're missing
opsSend a batch of ops
ackConfirm integration of received ops
nackReject ops for specific reasons
snapshotTail catch-up for late joiners

Rejection Reasons (Nack)

When a peer rejects ops, it sends a nack with a categorical reason:

type NackReason =
  | 'invalid-kind'          // unknown op kind
  | 'hash-mismatch'         // content hash doesn't match
  | 'missing-dependency'    // previousHash not in local log
  | 'apply-failed'          // decomposition/store error
  | 'protocol-version'      // unsupported wire version
  | 'destructive-op'        // safety gate violation
  | 'bulk-delete'           // bulk delete blocked
  | 'system-modification'   // system file modification
  | 'quarantine-required'   // suspicious change
  | 'rate_limited'          // rate limiter tripped

Rejection reasons are grouped — multiple rejected hashes for the same reason produce a single nack.

Iroh QUIC Transport

Iroh is the north-star P2P transport. It uses QUIC for multiplexed bidirectional streams with ALPN-based protocol selection.

const transport = await IrohSyncTransport.create({
  alpns: ['trellis-sync/1'],  // protocol identifier
  secretKey: […],             // deterministic identity (optional)
})

// Share this ticket with peers:
const ticket = transport.ticket()
// "trellis-sync/1@10.0.0.5:4001#…"

// Connect to a peer:
await transport.connectToPeer(ticketStr, 'peer-id', 'Alice')

// Send a message:
await transport.send('peer-id', {
  version: 1,
  type: 'ops',
  peerId: localId,
  ops: [op1, op2, op3],
})

Each send opens its own QUIC connection. Peers are auto-registered on incoming connections — true bidirectional communication without manual peer discovery.

CRDT-Style Reconciliation

When two peers diverge (both have unique ops after a common ancestor), the reconciler merges them:

Algorithm:
  1. Find the fork point (last common op hash)
  2. Split each stream into: shared prefix + unique suffix
  3. Detect conflicts in unique portions
  4. Interleave unique ops by timestamp (causal order)
  5. Feed unique ops to the integrator

reconcile(opsA, opsB) → ReconcileResult {
  merged:       [...shared, ...interleaved],
  uniqueToA:    [...],
  uniqueToB:    [...],
  forkPoint:    "trellis:op:abc…",
  clean:        true/false,
  conflicts:    [ReconcileConflict, …]
}

Conflict detection: two ops conflict when they both mutate the same file in non-commutable ways (e.g. both fileModify the same path).

Branch Concurrency Modes

Each branch carries a linear flag that controls how the sync engine reconciles divergent streams:

ModeBehaviorUse Case
linear: true default Fast-forward only. Push rejected if remote has diverged. main, release branches, CI-gated
linear: false CRDT-style concurrent appends. Reconciler merges divergent sub-chains. Feature branches, multi-device editing 
// In sync-engine.ts
if (branchPolicy.linear) {
  // Pre-filter dupes, hand new ops to integrator
  const newOps = msg.ops.filter(o => !localHashes.has(o.hash))
  onOpsReceived(newOps)
} else {
  // Reconcile divergent streams, hand uniqueToB to integrator
  const { uniqueToB } = reconcile(localOps, msg.ops)
  onOpsReceived(uniqueToB)
}

Full-State Sync Extensions

Beyond op-stream replication, Trellis supports full-state sync for cross-environment sync (3.4.1+):

MessagePayloadUse Case
graph-snapshotSQLite DB binaryLate-joiner full catch-up
lane-journalJSONL opsAgent lane state
decision-traceJSON audit trailReasoning provenance
entity-deltaIncremental changesEfficient graph updates

An environment variable TRELLIS_SYNC_ENV controls sync policy — production environments enforce safety gates (block destructive ops, bulk deletes, system modifications). Suspicious changes go to quarantine for manual review.
