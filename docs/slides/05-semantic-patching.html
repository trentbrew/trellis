Line Diffs vs. Semantic Patches

Git tracks changes as line-by-line text diffs. Trellis records what structurally happened to the code.

A variable rename across 47 lines:

Git line diff (12 lines of changes):
- function calculatePrice(base, tax) {
+ function calculateTotal(base, tax) {
-   return base * (1 + tax);
+   return base * (1 + tax);
  ... (40 more lines where
       "calculatePrice" → "calculateTotal")

Trellis semantic patch (1 op):
{ kind: 'symbolRename',
  entityId: 'FunctionDef:auth.ts:calculatePrice',
  oldName: 'calculatePrice',
  newName: 'calculateTotal' }

Parser Adapter Interface

Trellis supports pluggable language parsers. The TypeScript adapter is a Tier 1 regex-based implementation; tree-sitter can be swapped in for full Tier 2 accuracy.

export interface ParserAdapter {
  languages: string[];           // ['typescript', 'javascript', …]

  parse(content: string, filePath: string):
    ParseResult                  // AST → graph entities

  diff(oldResult: ParseResult, newResult: ParseResult):
    SemanticPatch[]              // old → new patches
}

export interface ParseResult {
  fileEntityId: string;
  filePath: string;
  language: string;
  declarations: ASTEntity[];    // functions, classes, interfaces, …
  imports: ImportRelation[];    // import statements
  exports: ExportRelation[];    // export statements
}

AST Entity Model

Top-level declarations become graph entities with stable IDs derived from structural position — not line numbers — so identity survives reformatting.

export interface ASTEntity {
  id: string;            // FunctionDef:auth.ts:calculatePrice
  kind: ASTEntityKind;     // FunctionDef | ClassDef | InterfaceDef |
                          //  TypeAlias | EnumDef | VariableDecl |
                          //  MethodDef | PropertyDef | Constructor
  name: string;            // "calculatePrice"
  scopePath: string;       // "MyClass.calculatePrice"
  span: [number, number];  // byte offsets (for roundtrip)
  rawText: string;         // exact source
  signature: string;       // normalized (no comments/whitespace)
  children: ASTEntity[];   // nested declarations
}

// Import/Export
interface ImportRelation {
  source: string;        // module path
  specifiers: string[];  // ['default', '{ Named }']
  isDefault: boolean;
  isNamespace: boolean;
  rawText: string;
  span: [number, number];
}

Semantic Patch Types

Eight patch kinds cover all code-level changes:

export type SemanticPatch =
  | { kind: 'symbolAdd';
      entity: ASTEntity }

  | { kind: 'symbolRemove';
      entityId: string;
      entityName: string }

  | { kind: 'symbolModify';
      entityId: string;
      oldSignature: string;
      newSignature: string;
      oldRawText: string;
      newRawText: string }

  | { kind: 'symbolRename';
      entityId: string;
      oldName: string;
      newName: string }

  | { kind: 'symbolMove';
      entityId: string;
      oldFile: string;
      newFile: string }

  | { kind: 'importAdd' | 'importRemove' | 'importModify';
      fileId: string; source: string; specifiers: string[] }

  | { kind: 'exportAdd' | 'exportRemove';
      fileId: string; name: string }

A single file save typically produces both a vcs:fileModify (Tier 0) and a set of semantic patches (Tier 2) — making the same change queryable at both levels.

Patch Commutativity

Two patches commute when they can be applied in either order with the same result. This table is the merge engine's decision table:

Patch APatch BCommute?
symbolModify(f1)symbolModify(f2)Yes
symbolModify(f1)symbolModify(f1)No — structural conflict
symbolRename(f1)symbolModify(f1)No — auto-resolvable
symbolMove(f1)symbolModify(f1)Yes
symbolRemove(f1)symbolModify(f1)No — delete/edit conflict
importAdd(file)importAdd(file)Yes — idempotent

The merge engine checks entity-ID overlap to decide. No overlap = commute.

Structured Merge Conflicts

When patches don't commute, Trellis produces a structured conflict — not <<<<< text markers.

export interface SemanticMergeConflict {
  entityId: string;          // "FunctionDef:auth.ts:encrypt"
  entityName: string;        // "encrypt"
  entityKind: string;        // "FunctionDef"
  filePath: string;          // "src/auth.ts"
  ours: SemanticPatch;       // the local patch
  theirs: SemanticPatch;     // the remote patch
  suggestion?:              // auto-merge hint
    | 'accept-ours'
    | 'accept-theirs'
    | 'combine'
}

export interface SemanticMergeResult {
  clean: boolean;
  patches: SemanticPatch[];
  conflicts: SemanticMergeConflict[];
}

The conflict names the entities and operations involved — a developer can understand and resolve it programmatically, or build a UI that shows both sides of the same symbol.

Graph-Native Diff Engine

The diff engine compares two graph states (by op hash or branch head) and produces a list of semantic patches:

interface DiffResult {
  patches: SemanticPatch[];     // what changed structurally
  filesChanged: string[];        // which files were affected
  stats: {
    added: number;
    modified: number;
    removed: number;
    renamed: number;
    moved: number;
  };
}

// Tier 0 fallback (before AST parsing):
interface FileLevelDiff {
  kind: 'fileAdded' | 'fileModified'
      | 'fileDeleted' | 'fileRenamed';
  path: string;
  oldContentHash?: string;
  newContentHash?: string;
  unifiedDiff?: string;  // classic unified diff
}
