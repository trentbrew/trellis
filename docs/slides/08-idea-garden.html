The Problem: Lost Context

In Git, abandoned work is invisible. Stale branches get pruned, stashes expire, lost commits become unrecoverable.

Git reality

  • Stale branch: git branch -D — gone forever
  • Stash entry: expires after 90 days
  • Lost commit: requires reflog arcana to recover
  • No way to search "what did I try last time?"

Trellis reality

  • Every op survives — immutable causal stream
  • Abandoned work stays queryable
  • AI-drafted intent summaries
  • Keyword and semantic vector search

Idea Clusters

An Idea Cluster is a contiguous sequence of ops in the causal stream that were never incorporated into a milestone and were later diverged from.

interface IdeaCluster {
  id: string;            // cl-8f3a…
  ops: VcsOp[];
  firstOp: string;       // hash of first op
  lastOp: string;        // hash of last op
  affectedFiles: string[];
  affectedSymbols: string[];  // Tier 2
  estimatedIntent: string;    // AI summary (stored as fact)
  intentEmbedding?: number[];  // vector for search
  createdAt: string;     // timestamp of first op
  abandonedAt: string;   // when user diverged
  status: 'abandoned'
       | 'draft'
       | 'revived';
}

The cluster is derived from the op stream — it is a query view, not a stored entity. The estimatedIntent is materialized as a graph fact for fast search.

Detection Heuristics

The system identifies idea clusters by analyzing the causal stream:

┌─────────────────────────────────────────┐
│  Context-switch detection                 │
│  Files shift: src/auth/* → src/ui/*       │
│  → preceding un-milestoned ops = cluster   │
├─────────────────────────────────────────┤
│  Branch abandonment                       │
│  No new ops on a branch for N days        │
│  → un-milestoned ops = cluster            │
├─────────────────────────────────────────┤
│  Revert detection                         │
│  File content hash returns to prior value │
│  → reverted ops = cluster                 │
└─────────────────────────────────────────┘
interface ClusterDetector {
  name: string;
  detect(
    stream: VcsOp[],
    milestones: Milestone[]
  ): IdeaCluster[];
}

Intent Summarization

estimatedIntent is materialized as a graph fact, not computed on the fly. A background job handles generation:

1. Detection trigger:
   ClusterDetector finds a new cluster
   → queues summarization job

2. LLM call:
   "Summarize this cluster in one sentence"
   Context: semantic patches + affected files

3. Storage:
   Fact { e: 'cluster:cl-8f3a',
          a: 'estimatedIntent',
          v: 'Cache auth tokens to avoid re-fetch' }
   Fact { e: 'cluster:cl-8f3a',
          a: 'intentEmbedding',
          v: [0.23, -0.45, 1.02, …] }  // 768-dim vector

4. Recomputation:
   Only when cluster ops change (rare)

Both keyword CONTAINS and vector similarity search work against materialized facts.

Searching the Garden

Because clusters are derived from graph entities, they're fully queryable:

-- "Did I ever try caching in the auth module?"
SELECT ?intent ?created ?files
WHERE {
  [?c "type"            "IdeaCluster"]
  [?c "status"          "abandoned"]
  [?c "estimatedIntent" ?intent]
  [?c "affectedFile"    ?f]
  [?c "createdAt"       ?created]
  FILTER contains(?f, "auth")
}
ORDER BY ?created DESC

For deeper semantic search, the AI interop layer accepts natural language:

// NL query → search across idea clusters
const results = await kernel.queryNatural(
  'find abandoned attempts at recursive tree traversal',
  { provider: nlProvider }
);

Reviving an Idea

Turning abandoned work back into active development:

# List all idea clusters
$ trellis garden list

CLUSTER        INTENT                   FILES    STATUS
cl-8f3a        "cache auth tokens"      3        abandoned
cl-2b1c        "extract error handler"   1        draft
cl-9e7d        "retry oauth flow"       2        abandoned

# Show details of a cluster
$ trellis garden show cl-8f3a

# Revive — replay cluster ops onto current head
$ trellis garden revive cl-8f3a \
    --branch "retry-token-cache"

Reviving replays the cluster's ops onto the current branch head, using the semantic merge engine to handle conflicts with intervening changes.

Retention Policy

Unlike Git's aggressive garbage collection, Trellis retains all ops by default:

interface RetentionPolicy {
  archiveAfterDays?: number;   // auto-archive after N days
  compressArchived?: boolean;  // store only summary + entry point
  neverPurge: boolean;         // default: true
}

// Unlike Git where:
//   git gc  → prunes unreachable objects
//   git stash drop → gone forever
//
// Trellis keeps everything. Archived clusters are compressed —
// summary + diff kept, details available on demand.
