What Is EQL-S?

EQL-S (Entity Query Language — Structured) is a declarative DSL for querying the EAV store, inspired by Datalog and tuple-relational calculus.

SELECT ?e ?name
WHERE {
  [?e "type"    "Project"]
  [?e "name"    ?name]
  (?e "memberOf" ?org)
}
FILTER ?name != "archived"
ORDER BY ?name ASC
LIMIT 10

Query AST

A query is a structured object — parsed from the DSL, but also constructible programmatically:

export interface Query {
  select:     string[];     // variables to project
  where:      Pattern[];    // conjunction of patterns
  filters:    Filter[];     // post-match predicates
  aggregates: Aggregate[];  // count, sum, avg, min, max, collect
  orderBy:    OrderBy[];    // sort specification
  limit:      number;       // max results (0 = unlimited)
  offset:     number;       // skip N results
}

export type Pattern =
  | FactPattern        // [?e "attr" ?v]
  | LinkPattern        // (?src "rel" ?tgt)
  | NotPattern         // NOT [pattern]
  | OrPattern          // OR { } { }
  | RuleApplication    // ruleName(?x, ?y)

Pattern Types

Five pattern kinds cover the core query primitives. Each pattern matches against the EAV store's indexes:

PatternDSL SyntaxMatches
FactPattern[?e "attr" ?v]Triple (e, a, v) via AVE index
LinkPattern(?src "rel" ?tgt)Link (e1, a, e2) via link index
NotPatternNOT […]Zero matches for inner pattern
OrPatternOR {…} {…}Any branch matches
RuleApplicationancestor(?x, ?y)Registered Datalog rule

Variables start with ?. Literals are bare strings/numbers.

Execution Model

The QueryEngine evaluates patterns sequentially — each pattern filters/refines the binding set from the previous one.

execute(query):
  1. bindings = [ {} ]          // start with one empty binding
  2. for each pattern in where:
       bindings = evalPattern(pattern, bindings)
       // each pattern joins its matches with prior bindings
  3. apply filters   → predicate on bound variables
  4. apply aggregates → group + reduce (count, sum, …)
  5. apply ordering   → sort by variables
  6. apply offset/limit → paginate
  7. project select   → shape output columns
  • Three indexes (EAV, AEV, AVE) make each pattern evaluation a hash lookup, not a full scan
  • Link indexes work the same way for graph traversal
  • Results are deduplicated by variable signature
  • No query plan optimization — simple sequential evaluation

Datalog Rules & Recursion

DatalogRuntime wraps the QueryEngine and adds rule registration. Rules enable transitive closure — the killer feature for graph queries.

// "Find all ancestors" in one rule call:
SELECT ?ancestor
WHERE { ancestor(?x, ?y)
        [?y "name" ?ancestor] }

Three built-in rule constructors:

  • transitiveClosureRules(name, attr) — forward reach
  • reverseReachabilityRules(name, attr) — backward reach
  • siblingRules(name, attr) — shared-parent siblings
// ancestor(x, y) :- [?x "parent" ?y]
// ancestor(x, y) :- [?x "parent" ?z], ancestor(?z, ?y)
{
  name: 'ancestor',
  params: ['x', 'y'],
  body: [
    { kind: 'fact', entity: variable('x'),
                     attribute: literal('parent'),
                     value: variable('y') },
    { kind: 'rule', name: 'ancestor',
                     args: [variable('y'), variable('z')] }
  ],
  filters: []
}

Max recursion depth: 32 (prevents infinite loops).

The parseSimple() Helper

For quick interactive queries, parseSimple() converts a friendly shorthand into full EQL-S:

Input:
  find ?e where type = "Project"

Output:
  SELECT ?e
  WHERE {
    [?e "type" "Project"]
  }
Input:
  find ?e ?title where status != "archived"
    and name contains "auth"

Output:
  SELECT ?e ?title
  WHERE {
    [?e "status" ?_status ]
    [?e "name"  ?title  ]
  }
  FILTER ?_status != "archived"
  FILTER ?title contains "auth"

EQL-S for VCS

Because everything is a graph entity, VCS primitives are queried the same way as any data:

-- Milestones by Alice
SELECT ?m ?msg
WHERE {
  [?m "type"      "Milestone"]
  [?m "createdBy" "identity:alice"]
  [?m "message"    ?msg]
}
ORDER BY ?createdAt DESC

-- Milestones touching a file
SELECT ?m ?msg
WHERE {
  [?m "type"      "Milestone"]
  [?m "message"   ?msg]
  [?m "affectsFile" "src/auth/provider.ts"]
}

-- Decisions affecting an entity
SELECT ?d ?rationale
WHERE {
  [?d  "type"    "Decision"]
  (?d  "about"    ?e)
  [?e  "entityId" "src/auth.ts"]
}

-- All branches forked from main
SELECT ?b ?created
WHERE {
  [?b "type"      "Branch"]
  (?b "forkedFrom" "branch:main")
  [?b "createdAt"  ?created]
}
