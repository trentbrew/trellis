EQL-S: Entity Query Language

A structured, Datalog-inspired pattern-matching query language for the EAV graph

Source: src/core/query/engine.ts · src/core/query/parser.ts · src/core/query/datalog.ts

What Is EQL-S?

EQL-S (Entity Query Language — Structured) is a declarative DSL for querying the EAV store. It is inspired by Datalog and tuple-relational calculus.

Core philosophy

  • Pattern matching: describe what you want, not how to find it
  • Variables: bind entities and values in the result set
  • Composition: patterns chain as conjunctions; filters and aggregates compose on top
  • Recursion: Datalog rules enable transitive closure

Syntax overview

SELECT ?e ?name
WHERE {
  [?e "type" "Project"]
  [?e "name" ?name]
  (?e "memberOf" ?org)
}
FILTER ?name != "archived"
ORDER BY ?name ASC
LIMIT 10

Query AST

A query is a structured object — parsed from the DSL but also constructible programmatically:

export interface Query {
  select:   string[];      // variables to project
  where:    Pattern[];      // conjunction of patterns
  filters:  Filter[];       // post-match predicates
  aggregates: Aggregate[];   // count, sum, avg, min, max, collect
  orderBy:  OrderBy[];      // sort specification
  limit:    number;         // max results (0 = unlimited)
  offset:   number;         // skip N results
}

export type Pattern =
  | FactPattern    // [?e "attr" ?v]
  | LinkPattern    // (?src "rel" ?tgt)
  | NotPattern     // NOT [pattern]
  | OrPattern      // OR { } { }
  | RuleApplication // ruleName(?x, ?y)

Pattern Types

Five pattern kinds cover the core query primitives:

PatternDSLMatches
FactPattern[?e "attr" ?v]Triple (e, a, v)
LinkPattern(?src "rel" ?tgt)Link (e1, a, e2)
NotPatternNOT […]Zero matches for inner
OrPatternOR {…} {…}Any branch matches
RuleApplicationancestor(?x, ?y)Registered Datalog rule

Execution Model

The QueryEngine evaluates patterns by matching fact/link patterns against the store, binding variables, then applying filters, aggregates, and ordering.

execute(query):
  1. results = evaluatePatterns(query.where, [{}])
     // Start with one empty binding,
     // each pattern refines the set
  2. apply filters   → filter rows
  3. apply aggregates → group + reduce (count, sum, …)
  4. apply ordering   → sort by variables
  5. apply offset/limit → paginate
  6. project select   → shape output columns
  • Three indexes (EAV, AEV, AVE) make each pattern evaluation a hash lookup, not a scan
  • Link indexes work the same way for graph traversal
  • Results are deduplicated by variable signature

Datalog Rules & Recursion

DatalogRuntime wraps the QueryEngine and adds rule registration. Rules enable transitive closure — the killer feature for graph queries.

// "Find all ancestors" in one rule call:
SELECT ?ancestor
WHERE { ancestor(?x, ?y) [?y "name" ?ancestor] }

Three built-in rule constructors are provided:

  • transitiveClosureRules(name, attr) — forward reach
  • reverseReachabilityRules(name, attr) — backward reach
  • siblingRules(name, attr) — shared-parent siblings
// Rule: ancestor(x, y) :- [?x "parent" ?y], ancestor(?y, ?z)
{
  name: 'ancestor',
  params: ['x', 'y'],
  body: [
    { kind: 'fact',
      entity: variable('x'),
      attribute: literal('parent'),
      value: variable('y') },
    { kind: 'rule', name: 'ancestor',
      args: [variable('y'), variable('z')] }
  ],
  filters: []
}

Max recursion depth: 32 (prevents infinite loops).

The parseSimple() Helper

For quick interactive queries, parseSimple() converts a friendly shorthand into full EQL-S:

Input:
  find ?e where type = "Project"

Output:
  SELECT ?e
  WHERE {
    [?e "type" "Project"]
  }
Input:
  find ?e ?title where status != "archived" and name contains "auth"

Output:
  SELECT ?e ?title
  WHERE {
    [?e "status" ?_status]
    [?e "name" ?title]
  }
  FILTER ?_status != "archived"
  FILTER ?title contains "auth"

EQL-S in the VCS Context

Because everything in Trellis is a graph entity, VCS primitives are queried the same way as any other data:

-- Find all milestones by Alice on the main branch
SELECT ?m ?msg
WHERE {
  [?m "type"       "Milestone"]
  [?m "createdBy"  "identity:alice"]
  [?m "message"    ?msg]
}
ORDER BY ?createdAt DESC

-- Find milestones that touched a specific file
SELECT ?m ?msg
WHERE {
  [?m "type"      "Milestone"]
  [?m "message"   ?msg]
  [?m "affectsFile" "src/auth/provider.ts"]
}

-- Trace all decisions affecting an entity
SELECT ?d ?rationale
WHERE {
  [?d "type"      "Decision"]
  [?d "context"   ?ctx]
  (ctx "about" ?e)
  [?e "entityId"  "src/auth.ts"]
}
