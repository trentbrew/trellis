What Are the Five Pillars?

TrellisVCS is organized around five core architectural principles. Together, they transform version control from a file-tracking tool into a semantic, auditable, collaborative state engine.

#PillarCore Promise
1Causal StreamEvery change is an immutable, content-addressed op in a causal chain.
2Semantic PatchingCode changes are understood as AST-level semantic diffs, not line patches.
3Narrative MilestonesHuman-curated checkpoints give meaning to the raw op stream.
4Governance SubgraphIdentity, signing, and authorization live in the data itself.
5Idea GardenAbandoned exploration is never lost — it's a searchable asset.

1. The Causal Stream

VCS Immutable audit log

A fine-grained, immutable ledger of every semantic change. Think of it as the "flight recorder" — every save, every file change, every branch operation is recorded as an op.

op1 ← op2 ← op3 ← op4 ← op5
 │       │       │       │       │
 ↓       ↓       ↓       ↓       ↓
SHA-256 SHA-256 SHA-256 SHA-256 SHA-256
 │       │       │       │       │
previousHash links to the prior op's hash

Key property: Each op's hash covers its content and its causal link to the previous op. Rewriting any op invalidates every successor.

2. Semantic Patching

Semantic AST-level diffs

Instead of line-level diffs, Trellis understands code as a tree. A variable rename across 47 lines is one symbolRename op, not 47 text edits.

Patch TypeWhat It Means
symbolAddA new declaration was introduced.
symbolRemoveA declaration was deleted.
symbolModifyA declaration's body changed.
symbolRenameA symbol was renamed (identity preserved).
symbolMoveA declaration moved to another file.
importAddA new import relationship was added.

4. The Governance Subgraph

Kernel Identity & authorization

Identity and permissions are built into the data structure — not a third-party server.

Identity Entity

entity: identity:alice
  ├─ type: "Identity"
  ├─ publicKey: Ed25519...
  └─ did: did:key:z6Mk...

The private key is never synced. Only the public key and DID are graph entities.

Policy Entity

entity: policy:protect-main
  ├─ type: "Policy"
  ├─ target: "branch"
  ├─ targetPattern: "main"
  ├─ action: "push"
  ├─ minSignatures: 2
  ├─ requiredSigner: identity:alice
  └─ requiredSigner: identity:bob

5. The Idea Garden

Semantic Searchable exploration archive

In Git, abandoned work is invisible. In Trellis, the causal stream is immutable — every op survives. The Idea Garden is a query layer over un-milestoned ops.

$ trellis garden list

CLUSTER         INTENT                    FILES         STATUS
cl-8f3a…        "cache auth tokens"       3 files       abandoned
cl-2b1c…        "extract error handler"   1 file        draft
cl-9e7d…        "retry oauth flow"        2 files       abandoned

Each cluster gets an AI-drafted intent summary, stored as a graph fact and vector-indexed for semantic search.

Architectural Invariants

Trellis adheres to five non-negotiable constraints that preserve local-first ownership and agentic inspectability:

  • No cloud server required. Works fully offline; relays are optional.
  • Local state is primary. Every node owns its graph; sync is replication, not ownership transfer.
  • Every mutation is a durable op. No staging area — changes become inspectable ops automatically.
  • Peers validate through identity + signatures + causal history. No trusted relay.
  • Browser compatibility without compromise. Local ownership is preserved even in browser shells.
