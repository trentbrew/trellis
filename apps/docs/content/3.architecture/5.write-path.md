# Write Path

Every file change that lands on disk is journaled into the op-log unless explicitly excluded. Capture is **opt-out** — the default is to record everything, and the exclusion surface is where you declare what stays out.

## Why opt-out

Under opt-in capture, nothing gets journaled until something explicitly triggers reconciliation. A new write path — a different agent harness, a hand-edit in vim, a forgotten script — defaults to **silently missing** from the op-log. That gap produced the 9801056-class silent revert: `git sync` materialized stale op-log state over newer disk content, wiping work without warning.

Opt-out inverts the failure mode:

| Model | Default | Worst case |
|-------|---------|------------|
| Opt-in | Files not journaled | Silent loss |
| Opt-out | Everything journaled | Noise in the op-log |

Silent loss is unrecoverable. Noise is scrubbable. That is the correct trade-off.

## Architecture

```text
Disk write        FileWatcher          Ingestion          Op-log
    │                 │                    │                  │
    ├─ file:add ──────►├─ hash + diff ─────►├─ vcs:fileAdd ────►│
    ├─ file:modify ───►├─ hash + diff ─────►├─ vcs:fileModify ─►│
    ├─ file:delete ───►├─ detect missing ──►├─ vcs:fileDelete ─►│
    │                 │                    │                  │
    │            per-path filter:    hash/valid/not-excluded
    │            .trellisignore
    │            self-observation: exclude ops.json, blobs/, lanes/
    │            worktrees/ in scope
```

The `FileWatcher` runs continuously as a daemon beneath all agent harnesses. It hashes changed files, diffs against the current op-log state, and journals `vcs:fileAdd`, `vcs:fileModify`, and `vcs:fileDelete` ops incrementally — agnostic to whether the write came from Claude Code, opencode, Cursor, or a human editor.

The watcher excludes its own storage (`.trellis/ops.json`, `.trellis/blobs/`, `.trellis/lanes/`) to prevent a self-observation loop, but keeps `.trellis/worktrees/` in scope so lane-isolated edits are captured.

## Exclusion surface

A `.trellisignore` file at the repo root, with `.gitignore`-compatible syntax. Defined separately because the overlap with `.gitignore` is large but not exact:

| Path | Typically excluded? | Reason |
|------|---------------------|--------|
| `dist/`, `node_modules/`, `.git/` | Yes | Build artifacts and external deps — never graph-relevant |
| `*.swp`, `*~`, `.DS_Store` | Yes | Editor and OS noise |
| `.env.local` | Depends | May be graph-relevant in some repos |
| `.trellis/{ops.json,blobs/,lanes/,*.json}` | Hard-excluded | Op-log and blob storage — excluded to prevent self-observation loop |

## Git as downstream mirror

Because every write is journaled at source, `syncGitIntegration` never encounters un-journaled drift. Git is a one-way export — always reconcilable, never clobbering. ADR 0014 established this relationship: _Trellis owns semantics; git is downstream materialization._

## CLI

```bash
# Manual reconciliation (if the daemon isn't running)
trellis git journal catch-up

# JSON output for automation
trellis git journal catch-up --json
# → {"journaled": 3, "unreconciled": []}
```

## Bridge: PostToolUse hook

For agent harnesses today, the OpenCode plugin spawns `trellis git journal catch-up` after every `Write | Edit | Bash` tool invocation. This closes the gap for the primary agent surface while the daemon is being built. The hook is harness-specific; the daemon is harness-agnostic.
