# Write Path

**Git is the sole authority over file bytes.** The op-log never materializes file state — architecturally, not config-gated. It records provenance: who/which agent, why, decision traces, milestone narratives — annotations hung off commits, queryable as graph entities, incapable of clobbering disk.

This supersedes the earlier opt-out capture model (ADR 0037). The recurrence of the 9801056-class silent revert — where `git sync` materialized stale op-log state over newer disk content — proved that two systems claiming authority over the same bytes is structurally unsound. Guards on the symptom (refuse-before-clobber) fail at whichever path nobody guarded. The fix is not a better guard; it is removing the second authority.

| Layer | Authority |
|-------|-----------|
| File bytes | **Git** — sole. Commits, merges, resets, reverts |
| Causal/provenance layer | **Op-log** — annotations only: issues, decisions, milestones, lane lifecycle, file notes, transcripts |
| Read-side graph | **EAV store** — decomposed from op-log; powers `query_graph`, IDE codebase-graph views |

## Architecture

```text
Disk edit → git worktree (per-lane branch)
                 │
                 ├─ git add/commit ────────────► bytes (git authoritative)
                 │
                 └─ annotation op ──────────────► op-log (provenance only)
                          vcs:fileNote { filePath, commitHash, agentId }
                          vcs:decisionRecord / milestone / lane lifecycle
```

The op-log is *incapable* of writing file state. There is no path — config, sync, or promote — where its view of a file can overwrite the working tree.

## Isolation (multi-agent)

Lane = git branch + worktree. `lanes.worktreeBind` is the isolation mechanism:
each agent edits in its own worktree, so one agent's `stash`/`revert`/`reset`
physically cannot touch another's files. Overlapping active lanes in a shared
tree are refused. Per-worktree git identity attributes commits; annotation ops
hang off `commitHash`.

## Indexing the workspace

`indexWorkspace` scans existing files and populates the graph as
**annotations** (file entities + `contains` links) so read-side consumers —
including the IDE's codebase-as-graph view — see the whole tree, without the
op-log claiming byte authority.

```bash
trellis init --index-workspace   # or: trellis init, then trellis index-workspace
```

## Provenance capture

Capture is opt-in per category, default off until a consumer exists. Graph
entities (issues, milestones, decisions, lane lifecycle) are always recorded —
they are the product and never touch bytes.

```jsonc
// .trellis/config.json
{
  "provenance": {
    "enabled": false,
    "capture": ["fileNotes", "agentRuns"],
    "transcripts": { "enabled": false, "sync": false },
    "sessionUsage": false
  }
}
```

No key can re-enable byte materialization — the validator rejects unknown
authority claims loudly.

## Promote

Lane promote = `git merge` of the lane branch (conflict classifier as a
pre-merge gate), then a chained `vcs:lanePromoteComplete` annotation carrying
the semantic diff and milestone narrative. No op replay, no reconciliation.

## Sync split

Graph ops sync through Trellis transports (safe by construction — no file
bytes in ops). File bytes sync via git remotes. Neither can clobber the other.

## CLI

```bash
trellis init --index-workspace   # populate graph from existing tree
trellis lane promote <id>        # git merge + annotation op
trellis git journal catch-up     # migration/diagnostic only — never in the write path
```
