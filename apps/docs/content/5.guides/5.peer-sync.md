# Peer Sync

`trellis wire` replicates graph operations directly between two repos over
[Iroh](https://iroh.computer) — no relay, no server in the middle. It is the first
shape of the transport-direct sync described in [Sync](/architecture/sync): one
peer serves, the other pulls.

Discovery is manual for now: peers exchange a **ticket**, and a rendezvous service
is deferred. Endpoint identity is derived from the repo identity, so a ticket is
stable across clones and renames.

## The three commands

| Command | What it does |
| --- | --- |
| `trellis wire ticket` | Print this repo's endpoint id and a shareable ticket, then exit |
| `trellis wire serve [--timeout <s>]` | Bind an endpoint, print the ticket, and serve ops to peers |
| `trellis wire pull --ticket <t> [--peer-id <id>] [--timeout <s>]` | Connect to a peer and integrate its ops |

## Serve from the source

On the repo that has the ops you want to share:

```bash
trellis wire serve --timeout 120
# endpoint 1f9c…8a2
# ticket   1f9c…8a2…<rest of ticket>
# serving 412 ops
```

Copy the `ticket` line. The endpoint stays open for `--timeout` seconds (or until
you press Ctrl-C; `--timeout 0` serves until interrupted).

## Pull on the other side

On the repo that should receive them:

```bash
trellis wire pull --ticket <ticket>
# endpoint 6b3d…f10
# pulling from remote
# applied 412 rejected 0
# ops 88 -> 500
```

Each incoming op is applied through the engine's sync gates, so validation,
dedupe, and rejection policy are the same as any other Trellis sync path —
`rejected` counts ops the gates refused.

## Notes

- **Pairwise only.** One peer pulls, one serves. Multi-peer meshes and discovery
  are out of scope for this slice (ADR 0060).
- **Tickets are shareable but identity-bound.** A ticket lets a peer connect to
  that endpoint; it does not grant write access to your graph.
- **Relays still have a role.** They remain useful for browsers, unreachable
  peers, backups, and hosted indexes — they accelerate or bridge sync, they do
  not own state.
